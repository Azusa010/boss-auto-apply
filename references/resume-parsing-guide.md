# 简历解析与交互式画像确认操作指南 (Resume Parsing & Questioning Guide)

本文档指导智能体在执行 BOSS 直聘自动化任务前，如何**通过阅读简历文件**或**发起交互式提问**动态确定候选人画像，并自动生成 `profile.config.json` 规则配置。

---

## 模式一：简历文件自动解析 (Resume First)

当用户在项目中提供了简历文件（支持 `.pdf`、`.md`、`.txt` 等格式）时，智能体优先自动读取并解析简历。

### 1. 运行提取脚本或直接阅读
- **Python 工具提取**：
  ```powershell
  python generic-skill/boss-auto-apply/scripts/parse-resume.py path/to/resume.pdf
  ```
  该脚本会自动利用 `pypdf` 抽取文本，并利用正则与启发式算法推断：
  - 毕业年份（如 `2026`、`2027`、`2028`）
  - 学历层次（`本科`、`硕士`、`博士`、`专科`）
  - 求职类型（若在校且为后届则推断为 `intern` 实习，毕业届推断为 `campus` 校招）
  - 提取关键技能（Python, LangChain, Agent, RAG 等）
- **Agent 直接阅读**：
  若简历为 Markdown 或纯文本文件，智能体可直接使用 `view_file` 读取并总结提取。

### 2. 向用户简要确认提取结果
即使解析成功，智能体也应向用户输出一份简洁画像摘要供用户一键确认，例如：
> “已为您解析简历：
> - **求职身份**：202X届本科在读（日常实习，或202X届应届毕业生）
> - **核心方向**：软件研发 / 后端开发 / 某技术方向
> - **期望城市**：上海 / 杭州 / 或全国远程
> - **每日投递限额**：150 次（平台单日上限）
> 请确认是否按照以上信息生成投递规则配置？”

## 模式二：交互式提问（问答协议 / Questionnaire Fallback）

当用户**未提供简历**或**简历信息不完整/模糊**时，智能体不得擅自臆测关键参数，必须通过精准简明的问题向用户提问。

### 核心 4 连问模板：

1. **求职身份与类型**：
   > “请问您目前的求职身份与诉求是？
   > - A. 在校日常实习（请告知每周可出勤天数与实习时长，如 3~5 天/周，3~6 个月）
   > - B. 202X 届应届生校园招聘 / 暑期实习
   > - C. 社招全职”

2. **学历层次与毕业年份**：
   > “请问您的学历背景与毕业年份是？（如：2027届本科、2025届硕士等）
   > *注：这直接决定我们在筛选时是否帮您自动穿透并剔除‘要求硕士/博士/特定名校’的岗位，避免浪费投递额度。*”

3. **目标岗位方向与核心技术栈**：
   > “您希望投递哪些技术方向或岗位关键词？
   > （例如：AI Agent / 智能体开发、大模型应用、全栈、Go后端等；是否有明确排除的岗位类型，如算法理论/数据标注/传统非AI？）”

4. **目标城市与黑名单公司**：
   > “您期望的工作城市是？是否有特定想要避开的企业黑名单（如某大厂关联公司）？
   > *（默认不对公司人数规模做限制，小微初创至千人大厂均可纳入）*”

## 规则配置转换协议 (Profile Generation Protocol)

根据简历或问答获取到的关键信息，智能体需将参数填入本地 `profile.config.json`。

### 1. 动态学历过滤正则生成逻辑
- **候选人为本科在读/本科毕业生时**：
  必须生成排他性正则，穿透核验完整 JD 正文（`.job-sec-text`），剔除硕博门槛与名校限定：
  ```json
  "degreeExcludeRegex": "(?:硕(?:士|研)|研究(?:生|生学历)|博士)(?:及以上|以上|优先|学历|学位)?|(?:仅限|面向|全日制|统招)(?:硕士|研究生|博士)|(?:985|211)(?:\\s*[/、或]\\s*(?:985|211))?(?:高校|大学)?(?:优先|毕业|统招|硬性|限定)|双一流高校优先|保研|研一|研二"
  ```
- **候选人为硕士/博士时**：
  放开硕士限制，仅保留对非目标学历或极度不符要求的排除规则（如专科硬性要求等，或留空）。

### 2. 动态用工类型匹配逻辑
- **如果是实习生**：
  - `mustHaveDevWords` 增加 `实习`、`元/天`、`在校`；
  - `excludeTitleRegex` 增加 `全职|社招|校招正式|合伙人|专家|主管|总监`。
- **如果是社招/校招**：
  - `excludeTitleRegex` 调整为过滤 `实习生|实习|兼职`，匹配正式职级。

### 3. 企业黑名单动态配置
- 用户指定的企业名称加入 `blacklistCompanies` 数组（如 `["某某公司A", "某某外包公司B"]`），脚本在抓取卡片和详情时会自动跳过。

### 4. 每日沟通额度
- 必须包含 `"quota": { "dailyLimit": 150 }`，确保遵守 BOSS 直聘平台每日 150 次主动沟通硬上限。
